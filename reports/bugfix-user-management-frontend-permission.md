# Bugfix Report：用户管理入口与前端权限保护

## 日期

2026-07-02

---

## 问题描述

### 问题1：Admin 导航入口不正确

admin 登录后，顶部导航显示的是「用户管理」而非「系统设置」。按需求规范，导航应显示：

- 首页
- 线索管理
- 系统设置

### 问题2：非 Admin 用户可访问用户管理页面

counselor（或 manager）登录后，直接访问 `/settings/users` 可以看到完整的用户管理页面，包括：

- 用户列表
- 「新增用户」按钮
- 所有操作按钮（编辑、禁用、重置密码）

虽然后端 API 会拒绝非 admin 的写操作，但前端不应展示该页面内容。

---

## 修复方案

### 修复1：TopNav 导航标签修正

**文件：** `frontend/components/TopNav.tsx`

**变更：** 第 69 行，将 admin 导航按钮的文字从「用户管理」改为「系统设置」。

- 链接目标不变，仍为 `/settings/users`
- 仅 admin（`userRole === "admin"`）可见该入口
- manager 和 counselor 不可见

### 修复2：settings/users 页面添加前端角色守卫

**文件：** `frontend/app/settings/users/page.tsx`

**变更：**

1. 新增 `roleChecked` 和 `isAdmin` 两个状态变量（第 20-21 行）
2. 新增 `useEffect`（第 62-74 行），在组件挂载时从 `localStorage` 读取用户角色并判断是否为 admin
3. 将原有的 `fetchUsers` 调用改为仅在 `isAdmin` 为 true 时才执行（第 76-80 行）
4. 添加两个早期返回分支：
   - **角色检查中**（`!roleChecked`）：显示 Loading 状态（第 194-203 行）
   - **非 admin 用户**（`!isAdmin`）：显示「无权限访问」提示（第 206-224 行）

**权限规则：**

| 角色       | 导航显示系统设置 | 可访问 /settings/users |
| ---------- | ---------------- | ---------------------- |
| admin      | ✅ 是            | ✅ 是                  |
| manager    | ❌ 否            | ❌ 否（显示无权限）     |
| counselor  | ❌ 否            | ❌ 否（显示无权限）     |
