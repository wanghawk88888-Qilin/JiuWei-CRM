# JiuWei CRM v0.2.1 — Resume Batch Import v1（简历批量导入）

- 版本：`v0.2.1`
- 功能名：`Resume Batch Import v1`
- 日期：2026-08-23
- 性质：生产系统增量升级（新增能力，不改旧行为）

---

## 1. 功能范围

在既有「单份简历导入」能力之上新增「简历批量导入」：

- 一次上传多份简历（上限 50 份，单份 ≤ 10MB，支持 `.docx` / `.pdf`）
- 逐文件独立解析，单个文件失败不影响整批
- 分层确定性字段识别（姓名 / 手机号 / 邮箱 / 学历 / 学校 / 专业 / 城市等）
- 姓名 / 手机号**可信度校验** + **冲突检测**，宁缺毋错
- 手机号**重复检测**（对 `leads.phone` 及批次内重复）
- 批量审核、人工修正、批量确认、批量生成正式 Lead
- 批次确认**幂等**，重复点击不会重复创建 Lead

明确**不包含**（留待后续增强版）：LLM / AI 简历解析、OCR、AI 课程建议（`intended_course_id` 本版本一律不自动填写）。

## 2. 架构设计

```
Text Extractor（resume_parser_service）
    ↓  文本型 PDF / DOCX；扫描件 → PDF_NO_EXTRACTABLE_TEXT
Rule Parser + Validator + Confidence/Conflict（resume_field_rules）
    ↓  纯函数、确定性、可单测
Duplicate Detector（resume_batch_service）
    ↓  对 leads.phone + 批次内去重
AI Enhancer（future — llm_extract_service，本版为 no-op 占位）
    ↓
Human Review（lead_draft_service.update_draft）
    ↓
Lead 生成（lead_draft_service.confirm_draft，幂等）
```

关键设计决策：

1. **宁可进人工确认，也不错误入库**。只有「姓名 + 手机号」同时高可信、且手机号未重复，草稿才进入 `ready`；其余一律 `needs_review` / `duplicate` / `failed`。
2. **每个文件一个事务边界**。解析循环里每个文件独立 try/except + rollback，单文件异常只回滚该文件。
3. **批次不引入基础设施**。解析用 FastAPI 原生 `BackgroundTasks`（轻量后台任务），不引入 Celery/Redis/MQ。
4. **复用旧数据模型**。`ResumeImportBatch → ImportLog（每文件一条）→ LeadDraft（每成功文件一条）`，不另起炉灶。

## 6. 文件解析规则（`resume_parser_service.py`）

- `.docx`：段落 + **表格单元格**（中文简历个人信息常为表格）都提取。
- `.pdf`：优先 PyMuPDF，回退 pdfplumber。
- 提取文本长度 < 10 字符 → 判定无可提取文本：PDF 报 `PDF_NO_EXTRACTABLE_TEXT`（疑似扫描件/图片版），DOCX 报 `DOCX_NO_EXTRACTABLE_TEXT`。
- **不做 OCR**。扫描件显式失败进人工，而非猜测。
- `.doc` 不纳入本版本（当前镜像无稳定转换器，不为此引入重型系统依赖）。

---

## 7. 姓名识别规则（`resume_field_rules.py`）

三层优先级，冲突一律不自动选择：

1. **显式标签**（高可信）：`姓名：` / `姓 名：` / `姓名 张三` / `Name:` / `个人姓名：` 等；表格型标签与值分行也支持。
2. **顶部个人信息区**：文档前 15 行，结合中文姓名长度（2–6 字）、手机号/邮箱邻近度、是否首行等打分。排除「个人简历/求职简历/个人信息/基本信息」等标题，排除「北京大学/字节跳动科技」等组织名，排除学历/婚姻/户籍等高频词。
3. **空格排版**：`张 三 → 张三`、`王 小 明 → 王小明`（纯中文去空格；英文名保留空格）。

多候选无法判定 → `NAME_CONFLICT`，状态 `needs_review`。

---

## 8. 手机号识别规则

- 正则：`1[3-9]\d{9}`（带数字前后瞻，避免身份证号误命中）。
- 原始格式统一标准化为 11 位：`13812345678` / `138 1234 5678` / `138-1234-5678` / `+86 13812345678` / `+86-138-1234-5678` / `8613812345678`。
- 高可信需满足至少一项：出现于 `手机/手机号/联系电话/电话/联系方式/Mobile/Tel/Phone` 附近，或位于顶部个人信息区。
- 负向标签（`紧急联系/公司电话/座机/家长/推荐人` 等）标记为"非本人"。
- 多候选无法判定 → `PHONE_CONFLICT`，状态 `needs_review`。

---

## 9. 冲突处理

| 场景 | 处理 |
|---|---|
| 多个姓名候选 | 不选，`NAME_CONFLICT` → `needs_review` |
| 多个手机号候选 | 不选，`PHONE_CONFLICT` → `needs_review` |
| 姓名缺失 | `NAME_MISSING` → `needs_review` |
| 手机号缺失 | `PHONE_MISSING` → `needs_review` |
| 负向标签号码（紧急联系人等） | 不当作本人号码 |

置信度：`high / medium / low / missing`。只有「姓名 high 且手机号 high」才 `auto_confirmable`。

---

## 10. 重复检测

- 建立 `leads.phone` 索引（双方都标准化后比对，容错旧数据格式）。
- 命中 → 草稿 `duplicate`，返回 `existing_lead_id / existing_lead_name / existing_phone`。
- 前端提示「系统中已存在相同手机号线索」，可「查看已有线索」跳 `/leads/{id}`，**不提供强制创建重复**。
- 批次内重复：第二个相同手机号的文件也标 `duplicate`（`in_batch: true`）。
- 批量确认前、人工修正后都会再次校验（防止解析后他人又创建了相同线索）。

- 新页面：`/leads/import-batch`（入口：线索管理页「批量导入简历」按钮）。

## 14. 回滚方案

若 v0.2.1 部署失败：

**A. 回滚应用（首选，schema 无需回滚）**

新增列全部 nullable、v0.2.0 代码从不读写它们；`resume_import_batches` 是 v0.2.0 完全不感知的新表。因此回退应用即可，库中多出的列/表是惰性的，不影响旧功能：

```bash
git checkout <v0.2.0 的 commit>
docker compose build backend frontend
docker compose up -d
```

**B. 回滚数据库文件（仅在迁移中途异常/断电等极端情况）**

```bash
docker compose stop backend
cp backend/data/jiuwei_crm.db.bak-v0.2.1-<时间戳> backend/data/jiuwei_crm.db
docker compose start backend
```

**C. 恢复镜像**

若需回到旧镜像：`docker tag` 保留的旧镜像重新标记为 latest，或 `docker compose up -d --no-build` 使用上次构建的镜像。

> 注意：SQLite 不支持安全地 `ALTER TABLE DROP COLUMN`（旧版本），不要尝试手工删列——那需要重建表，正是本项目禁止的操作。多出的列留着无任何代价。

## 15. 已知限制

1. 扫描版/图片型 PDF 无法识别（无 OCR），显式失败进人工——符合本版本约定。
2. 不解析 `.doc`（无稳定转换器，未引入重型依赖）。
3. 姓名/手机号识别是确定性规则，非 NER；复杂排版可能需人工确认（安全导向）。
4. `intended_course_id` 一律不自动填写，等 AI Course Suggestion。
5. 同步解析：50 份文件的解析在单个后台任务里串行执行，超大批次首次加载略有延迟；本版本不引入队列。
6. 不提供"强制创建重复 Lead"。
7. 单份导入旧流程沿用 `pending` 状态机，与批次状态机并存（有意为之，保证兼容）。

## 16. AI 后续扩展接口

解析代码已按 `Text Extractor → Rule Parser → Validator → Confidence/Conflict → AI Enhancer（future）→ Human Review` 分层：

- **插入点 1**：`llm_extract_service.enhance_resume_extract(text)` 现为 no-op 占位，批处理在 `resume_batch_service.process_single_file` 中调用它，未来接入真实 LLM 无需改动批次架构。
- **插入点 2**：`resume_field_rules.extract_profile` 输出 `name_confidence / phone_confidence / conflicts / candidates`，AI 可"提升置信度"或"消解冲突"——只需在调用方用 AI 结果覆盖相应字段，再走既有 `resolve_draft_status`。
- **插入点 3**：`intended_course_id` 字段在 Lead 与 LeadDraft 上均已存在，AI Course Suggestion 直接回填即可，规则层刻意不写它。
- **数据已就绪**：`lead_drafts.conflict_flags`（JSON）与 `name_candidates/phone_candidates` 为 AI 提供上下文。
