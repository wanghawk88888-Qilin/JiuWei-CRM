## 二、Dashboard 卡片跳转逻辑

四张统计卡改为整卡可点击的 `<button>`（保留原配色，增加 `cursor-pointer`、hover 上浮/阴影/border 强化、focus ring 键盘可达性）：

| 卡片 | 跳转 |
|------|------|
| 全部线索 | `/leads` |
| 今日新增 | `/leads?created=today` |
| 待跟进 | `/leads?followup=pending` |
| 已报名 | `/leads?status=enrolled` |

跳转后的线索列表会：

1. 从 URL 读取 `created` / `followup` / `status` 参数；
2. 顶部显示「当前筛选：今日新增 / 待跟进 / 已报名」提示 + 「清除筛选」按钮；
3. 筛选状态持久在 URL 中，刷新后仍保留（不依赖 React 内存 state）。

## 三、Admin / Counselor 权限矩阵

| 入口 | Admin | Counselor |
|------|-------|-----------|
| Dashboard summary（4 张卡数字） | 全局统计 | 仅 `owner_id == 自己` |
| Dashboard today-followups | 全局 | 仅 `owner_id == 自己` |
| Dashboard recent-leads | 全局 | 仅 `owner_id == 自己` |
| `GET /api/v1/leads` | 全局（可传 `owner_id` 过滤） | 强制 `owner_id == 自己`，无视 query |
| 卡片跳转后的列表 | 全局 | 强制本人，`owner` 过滤与卡片筛选同时生效 |

权限全部由**后端**保证（`_apply_lead_owner_filter` / `list_leads` 中 `role == "counselor"` 分支），前端仅做角色自适应的列显隐，不承担隔离职责。

## 四、Lead list 权限检查结果

核查 `GET /api/v1/leads`（`lead_service.list_leads`）：

- **Counselor 已正确只返回本人负责的 Lead** —— 现有逻辑中 `if current_user.role == "counselor": query = query.filter(Lead.owner_id == current_user.id)` 位于 `owner_id` 参数分支之前，**任何** `?owner_id=` 传参都无法绕过。
- **Admin 不受 owner_id 限制** —— 不传 `owner_id` 即返回全局。
- **owner_id 为空的线索不会错误归给 Counselor** —— 因为 `Lead.owner_id == current_user.id` 对 `NULL` 不成立，自然被排除；Admin 仍可见（`owner_name` 为 null，前端显示「未分配」）。
- 结论：**后端权限过滤已满足 P0 要求，本次无需最小修复，仅新增卡片筛选参数（同样经过该权限过滤）。**

## 五、owner / recent followup 字段语义

- **owner_name（咨询师 / 负责人）**：来源 `Lead.owner_id → User.real_name`；`owner_id` 为空返回 `null`，前端显示「未分配」。**禁止使用 `FollowUp.created_by` 当作负责人。**
- **last_followup_content（最近跟进）**：来源该线索最新一条有效 `FollowUp.content` 的简短摘要，超 50 字符截断并追加 `...`；无有效跟进时返回 `null`，前端显示「尚未跟进」（不再是 `-`）。
- **last_followup_at（最近跟进时间）**：仍来自最新有效 `FollowUp.created_at`，无跟进显示 `-`。
- **next_followup_at（下次跟进时间）**：继续展示 `next_followup_at`，无值显示 `-`。
- `owner_id` **保留**，仅调整 UI 语义，未修改数据库模型。

「最近跟进人」列已下线，线索列表中原「最近跟进人」列改为「最近跟进」（内容摘要）。`last_followup_by` / `last_followup_by_name` 字段在 schema 中保留（向后兼容），仅不再用于该列展示。

## 六、API 修改

### `GET /api/v1/leads`

新增可选 query 参数：

| 参数 | 值 | 语义 | 与 summary 同口径 |
|------|----|------|-------------------|
| `created` | `today` | `Lead.created_at` 当天 | 今日新增卡 |
| `followup` | `pending` | 存在非删除、`next_followup_at <= 今日 23:59:59` 的跟进 | 待跟进卡 |

响应 `items[]` 新增字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `owner_name` | `string \| null` | 负责人真实姓名；无 owner 为 `null` |
| `last_followup_content` | `string \| null` | 最近跟进内容摘要（≤50 字 + `...`）；无跟进为 `null` |

### `GET /api/v1/dashboard/today-followups` / `recent-leads`

响应项新增 `owner_name`（来源 `Lead.owner_id → User.real_name`）。

`/api/v1/dashboard/summary` 口径不变（原有 role 过滤已正确）。
