# Security & Gateway Upgrade — v0.1.2

**版本：** v0.1.2

**发布日期：** 2026-07-03

**升级类型：** 安全加固 / 网关层引入

**影响范围：** 部署架构（无业务代码变更）

---

## 一、升级背景

v0.1.1 已成功部署至阿里云 ECS，但存在以下生产安全风险：

| # | 问题 | 风险等级 |
|---|------|----------|
| 1 | 前端 HTTP 明文访问 (3100) | 🔴 高危 |
| 2 | 后端 API 直接公网暴露 (8100) | 🔴 高危 |
| 3 | 无统一入口，用户直接访问端口 | 🟡 中危 |
| 4 | 无 HTTPS 加密传输 | 🔴 高危 |
| 5 | 无反向代理层，缺少安全防护 | 🟡 中危 |

## 二、架构变化

### Before (v0.1.1)

```
Internet
   │
   ├── http://39.105.33.49:3100 ──► frontend:3000 (Next.js)
   │
   └── http://39.105.33.49:8100 ──► backend:8000  (FastAPI)
```

- 前端、后端各自暴露公网端口
- HTTP 明文传输
- 无统一入口
- 无反向代理

### After (v0.1.2)

```
Internet
   │
   ├── http://39.105.33.49  ──► 301 Redirect ──┐
   │                                             │
   └── https://39.105.33.49 ──► nginx:443 ──────┤
                                                 │
                           ┌─────────────────────┘
                           ▼
                      nginx (alpine)
                      :80  → 301 → :443
                      :443 → TLS 终结
                           │
              ┌────────────┼────────────┐
              │            │            │
              ▼            ▼            ▼
           /            /api        /health
     frontend:3000   backend:8000   nginx
     (Next.js)       (FastAPI)      (内置)
```

- 仅 nginx 暴露 80/443
- frontend/backend 仅容器内部通信
- HTTPS 加密（自签证书）
- HTTP 自动跳转 HTTPS
- 统一入口，安全头注入

## 四、Nginx 配置详解

**文件：** `nginx/nginx.conf`

```nginx
worker_processes auto;

events {
    worker_connections 1024;
}

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;

    sendfile        on;
    keepalive_timeout  65;

    # Gzip 压缩
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css text/xml text/javascript
               application/json application/javascript
               application/xml+rss image/svg+xml;

    # API 限流
    limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;

    # ── HTTP → HTTPS 跳转 ──
    server {
        listen 80;
        server_name _;
        return 301 https://$host$request_uri;
    }

    # ── HTTPS 主服务 ──
    server {
        listen 443 ssl;
        server_name _;

        ssl_certificate     /etc/nginx/certs/jiuwei-crm.crt;
        ssl_certificate_key /etc/nginx/certs/jiuwei-crm.key;

        ssl_protocols TLSv1.2 TLSv1.3;
        ssl_ciphers HIGH:!aNULL:!MD5;
        ssl_prefer_server_ciphers on;

        # 安全头
        add_header X-Frame-Options "DENY" always;
        add_header X-Content-Type-Options "nosniff" always;
        add_header X-XSS-Protection "1; mode=block" always;
        add_header Referrer-Policy "strict-origin-when-cross-origin" always;

        # ── 前端 ──
        location / {
            proxy_pass http://frontend:3000;
            proxy_http_version 1.1;

            proxy_set_header Host              $host;
            proxy_set_header X-Real-IP         $remote_addr;
            proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_set_header X-Forwarded-Host  $host;

            # WebSocket (Next.js HMR)
            proxy_set_header Upgrade   $http_upgrade;
            proxy_set_header Connection "upgrade";

            proxy_read_timeout 60s;
            proxy_connect_timeout 5s;
        }

        # ── 后端 API ──
        location /api {
            proxy_pass http://backend:8000;
            proxy_http_version 1.1;

            proxy_set_header Host              $host;
            proxy_set_header X-Real-IP         $remote_addr;
            proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_set_header X-Forwarded-Host  $host;

            proxy_read_timeout 60s;
            proxy_connect_timeout 5s;

            limit_req zone=api_limit burst=20 nodelay;
        }

        # ── 健康检查 ──
        location /health {
            access_log off;
            return 200 "OK";
            add_header Content-Type text/plain;
        }
    }
}
```

### 路由规则总结

| 请求路径 | 转发目标 | 说明 |
|----------|----------|------|
| `http://IP:80` | → 301 → `https://IP` | HTTP 强制跳转 |
| `https://IP/` | → `frontend:3000` | 前端页面 |
| `https://IP/api/*` | → `backend:8000/api/*` | 后端 API |
| `https://IP/health` | → nginx 直接返回 200 | 健康检查 |

### NEXT_PUBLIC_API_BASE_URL 变更说明

| 版本 | 值 | 前端 API 请求路径 |
|------|-----|-------------------|
| v0.1.1 | `http://localhost:8000` | `http://localhost:8000/api/v1/leads` (直接访问后端) |
| v0.1.2 | `""` (空字符串) | `/api/v1/leads` (相对路径 → nginx → 后端) |

配合 `api.ts` 中 `||` → `??` 的变更：
- `"" ?? "http://localhost:8000"` → `""` ✅ 相对路径
- `"" || "http://localhost:8000"` → `"http://localhost:8000"` ❌ 回退到旧行为

## 七、部署步骤

### 7.1 上传新文件到 ECS

```bash
# 在本地项目根目录
scp -r nginx/ root@39.105.33.49:/opt/jiuwei-crm/
scp docker-compose.yml root@39.105.33.49:/opt/jiuwei-crm/
scp frontend/lib/api.ts root@39.105.33.49:/opt/jiuwei-crm/frontend/lib/
```

### 7.2 在 ECS 上重建服务

```bash
ssh root@39.105.33.49
cd /opt/jiuwei-crm

# 停止旧容器
docker compose down

# 重新构建并启动（前端需要重新 build 以应用新的 API_BASE_URL）
docker compose up -d --build

# 验证服务状态
docker compose ps
```

### 7.3 验证

```bash
# 1. 确认 3100/8100 不再对外暴露
curl --connect-timeout 3 http://39.105.33.49:3100  # 应超时/拒绝
curl --connect-timeout 3 http://39.105.33.49:8100  # 应超时/拒绝

# 2. HTTP → HTTPS 跳转
curl -I http://39.105.33.49
# 期望: HTTP/1.1 301 Moved Permanently
#       Location: https://39.105.33.49/

# 3. HTTPS 前端可访问
curl -k https://39.105.33.49
# 期望: 返回前端 HTML

# 4. API 通过 /api 可访问
curl -k https://39.105.33.49/api/v1/health
# 期望: {"success":true,"message":"..."}

# 5. 健康检查
curl -k https://39.105.33.49/health
# 期望: OK

# 6. 检查安全头
curl -kI https://39.105.33.49 2>/dev/null | grep -E 'X-Frame|X-Content|X-XSS|Referrer'
```

### 7.4 浏览器访问

打开 `https://39.105.33.49`，首次访问会提示证书不受信任（自签证书），点击"高级"→"继续访问"即可。

## 十、总结

v0.1.2 在不修改任何业务代码的前提下，通过引入 Nginx 反向代理层，完成以下安全加固：

1. ✅ **统一入口** — nginx 作为唯一对外服务
2. ✅ **HTTPS 加密** — 自签证书实现 TLS 传输加密
3. ✅ **端口收敛** — 前端/后端端口不再公网暴露
4. ✅ **安全头注入** — X-Frame-Options, XSS Protection 等
5. ✅ **API 限流** — 10 req/s 基础防护
6. ✅ **客户端 IP 透传** — X-Forwarded-For 头
7. ✅ **HTTP 自动跳转 HTTPS** — 301 重定向

**安全状态：** 🔒 生产可用（自签证书为已知限制）
