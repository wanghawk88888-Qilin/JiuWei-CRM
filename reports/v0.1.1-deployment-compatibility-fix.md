# v0.1.1 Deployment Compatibility Fix

**Date:** 2026-07-03  
**Version:** v0.1.1 (Patch)  
**Type:** Deployment Compatibility Fix

---

## 一、问题描述

v0.1.0 部署至 ECS 后，发现两个兼容性问题：

| # | 问题 | 影响 |
|---|------|------|
| 1 | 前端登录页提示"网络连接失败" | Next.js 构建阶段未注入 `NEXT_PUBLIC_API_BASE_URL`，浏览器端请求了错误的 API 地址 |
| 2 | Backend Dockerfile 安装 `libmupdf-dev` | ECS 构建时 `apt-get` 非常慢或卡住，且 PyMuPDF pip wheel 已自带二进制依赖无需系统包 |

---

## 二、根因分析

### 2.1 前端 API Base URL 未被注入

- `frontend/lib/api.ts` 已正确使用 `process.env.NEXT_PUBLIC_API_BASE_URL || "http://localhost:8000"`
- 但在 `frontend/Dockerfile` 的 builder 阶段，未声明 `ARG NEXT_PUBLIC_API_BASE_URL` 和 `ENV NEXT_PUBLIC_API_BASE_URL`
- Next.js 在构建时（`next build`）会将 `NEXT_PUBLIC_*` 前缀的环境变量内联到客户端 bundle 中
- 构建阶段没有该变量 → 始终回退到 `http://localhost:8000` → ECS 用户浏览器请求 localhost 导致失败
- `docker-compose.yml` 中仅设置了 runtime `environment`，未设置 `build.args`，因此构建阶段无法读取

### 2.2 Backend libmupdf-dev 依赖

- `backend/Dockerfile` 包含 `apt-get install libmupdf-dev`
- PyMuPDF 从 v1.24.x 起提供预编译 wheel（`manylinux`），包含所需 native 库
- ECS 环境中 `apt-get` 下载速度不稳定，尤其在国内网络环境下
- 移除不影响 PDF 解析功能

## 四、Dockerfile 修改说明

### 4.1 frontend/Dockerfile

**修改前：**
```dockerfile
FROM node:22-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build
```

**修改后：**
```dockerfile
FROM node:22-alpine AS builder
WORKDIR /app

ARG NEXT_PUBLIC_API_BASE_URL
ENV NEXT_PUBLIC_API_BASE_URL=$NEXT_PUBLIC_API_BASE_URL

COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build
```

- `ARG` 声明接受构建参数
- `ENV` 将其转为环境变量，使 Next.js 构建阶段可以读取并内联到客户端 JS bundle

### 4.2 docker-compose.yml

**修改前：**
```yaml
frontend:
  build:
    context: ./frontend
    dockerfile: Dockerfile
  environment:
    - NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
```

**修改后：**
```yaml
frontend:
  build:
    context: ./frontend
    dockerfile: Dockerfile
    args:
      NEXT_PUBLIC_API_BASE_URL: ${NEXT_PUBLIC_API_BASE_URL:-http://localhost:8000}
  environment:
    - NEXT_PUBLIC_API_BASE_URL=${NEXT_PUBLIC_API_BASE_URL:-http://localhost:8000}
```

- `args` 将环境变量传入构建阶段（build time）
- `environment` 保留运行时（runtime）也可读取
- `${NEXT_PUBLIC_API_BASE_URL:-http://localhost:8000}` 语法：优先使用 shell 环境变量，未设置时默认 `http://localhost:8000`

### 4.3 backend/Dockerfile

**修改前：**
```dockerfile
FROM python:3.13-slim

WORKDIR /app

# Install system dependencies for PyMuPDF
RUN apt-get update && apt-get install -y --no-install-recommends \
    libmupdf-dev \
    && rm -rf /var/lib/apt/lists/*

# Install Python dependencies
...
```

**修改后：**
```dockerfile
FROM python:3.13-slim

WORKDIR /app

# Install Python dependencies
...
```

- 移除整个 `apt-get` RUN 指令块
- PyMuPDF 通过 pip wheel 安装时自带二进制依赖，无需系统级 muPDF 库
- 构建速度显著提升，国内网络环境下不再卡住

## 五、NEXT_PUBLIC_API_BASE_URL 构建注入说明

### 注入流程

```
Shell 环境变量                     Docker build arg            Next.js 构建时读取
─────────────────                ─────────────────            ──────────────────
NEXT_PUBLIC_API_BASE_URL  ──→  ARG NEXT_PUBLIC_API_BASE_URL  ──→  process.env.NEXT_PUBLIC_API_BASE_URL
       │                              │                                    │
       │                       ENV NEXT_PUBLIC_API_BASE_URL                │
       │                              │                                    │
       └──────────────────────────────┴────────────────────────────────────┘
                                内联到客户端 JS bundle
                                       │
                                浏览器直接使用该值请求 API
```

### Next.js NEXT_PUBLIC_ 约定

- Next.js 只将 `NEXT_PUBLIC_` 前缀的环境变量暴露给客户端
- 该注入发生在 `next build` 时，而非运行时
- 修改后必须重新 build，仅 restart 无效

## 七、ECS 更新步骤建议

### 步骤 1：拉取最新代码

```bash
cd /path/to/JiuWei-CRM
git pull origin main  # 或其他分支
git checkout <v0.1.1-tag>
```

### 步骤 2：设置环境变量

```bash
# 方式 A：创建 .env（推荐，永久生效）
echo 'NEXT_PUBLIC_API_BASE_URL=http://39.105.33.49:8100' > .env

# 方式 B：构建时临时传入
export NEXT_PUBLIC_API_BASE_URL=http://39.105.33.49:8100
```

### 步骤 3：重新构建并重启

```bash
# 停止现有服务
docker compose down

# 重新构建（必须 --no-cache 确保重读环境变量）
docker compose build --no-cache

# 启动
docker compose up -d
```

### 步骤 4：验证

```bash
# 检查 backend 健康
curl http://39.105.33.49:8100/api/v1/health

# 浏览器打开 frontend 并尝试登录
# http://39.105.33.49:3100
```
